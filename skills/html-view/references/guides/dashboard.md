# 看板设计

做 `layout: dashboard` 的报表，或画数据看板的界面稿时读本页。本页决定看板回答什么、先让读者看到什么；数据包写法见[报表流程](../artifacts/data.md)，界面稿写法见[界面稿](../artifacts/ui.md)。

读者看看板的顺序是：先看全局状态，再找出要处理的地方，需要时看细节。页面上的每个元素要么回答问题，要么指出问题，两样都不做的就删掉。

## 动手前写下四件事

1. **这一屏回答的问题**，如「十月经营是否正常，靠哪个渠道拉动」。一个看板只回答一个问题；有两个问题时拆成视图（`views`）或两份报表。
2. **回答它的 3–6 个数**，写进 `kpi` 块，最重要的放第一个。超过 6 个，读者就分不出主次；其余的放进图或表。
3. **什么算有问题**，写成数，如「转化率低于 10%」「连续两个月环比下降」。它决定哪张图、哪条记录要强调。
4. **每个大数和什么比**：上期（`compare` 含 `mom`）、去年同期（`yoy`）、目标或正常范围。没有可比对象的数不放进 KPI。

目标、阈值和正常范围来自用户或上游数据。没有就不画目标线，并在交付时说明缺什么，不自己定一个。

## 排版顺序

`dashboard` 版式固定为 KPI、图、表、叙述。图按声明顺序两张一行，数量为单数时最后一张占满一行；手机和打印改为单列。在这个框架内：

- 第一张图直接回答这一屏的问题：问「哪里要处理」时，放各项与目标或上期的差距；问「整体走得怎样」时，放趋势。其余拆解放在后面，需要逐条核对的记录放表格。手机首屏通常只放得下 KPI 和第一张图。
- 同一行两张图的内容量要相近。两三根柱的图和十几个月的趋势并排，会留下半张空卡；把小图排在一起，或把两三个值改成 KPI。
- 叙述只写页面上读不出的内容：口径缺口、有来源的原因、下一步。不要用句子复述 KPI，同一个数只下一次结论。

## 选图

位置和长度最容易读准，角度、面积和颜色深浅次之：

- 随时间变化用 `line` 或 `area`；类别比较用 `bar`（类名长或要排名）或 `column`。
- 与目标比时，数据集里放一列目标值。只看达成情况用 `bullet`（目标映射到 `target` 角色）；还要强调某一项时，用 `bar` 把实际和目标并排（`encode.value` 写成两个字段），因为 `bullet` 不绘制强调。各项共用一个目标或阈值时，用 `annotations` 的 `rule` 画一条参考线。
- 构成优先用 `share` 或排序后的 `bar`；`pie`、`donut` 只在一块明显占多数时使用。
- 颜色深浅只用在网格已占用位置的 `heatmap`、`calendar`。色相只区分类别，不表示大小。
- `gauge` 只放一个有固定上下限的值。

图题写读者要问的问题或指标名，如「各渠道收入与目标」。报表有多个视图时，同一图题要对每个视图都成立，不写只对某个视图成立的结论。

## 只强调有问题的地方

颜色由主题决定，不写颜色。读者该先看的记录或系列用 `emphasis` 标出，其余变淡；目标线和正常范围用 `annotations` 的 `rule`、`band` 画出。哪些图型支持、怎么写，见[声明通则](../charts/common.md)。一张图最多强调一处；处处强调就等于没有强调。

下例把各渠道的实际与目标并排，并强调未达标的渠道。被强调的一行保留图例颜色，其余变淡：

```json
{"type":"chart","id":"vs-target","dataset":"monthly","chart":"bar",
 "encode":{"category":"channel","value":["revenue","target"],"id":"channel"},
 "title":"各渠道收入与目标","emphasis":{"rows":["其他"]}}
```

- 强调和参考线按本期数据写，换期重建前重新核对。参考线的数值是手写的，来源写进图的 `subtitle`。
- `rows` 强调指向具体记录。报表有 `views` 时，被强调的记录要在每个视图里都存在，否则 `validate` 报错。

数字一致、缺失不当 0、小基数和未完结期间的提示，都由数据包规则保证（见[数据包](../artifacts/data-package.md)）。不要为了版面好看绕开这些规则，例如把缺失月份填 0 让折线连起来，或删掉 `sample` 让小样本比例不再提示。

## 界面稿里的看板

带筛选、可点击的看板原型还要做到：

- 顶栏放标题、日期范围和筛选，下面依次是 KPI、主图、拆解和明细列表；手机上按同样顺序排成单列。
- 为数据面板设计加载中、旧数据（标出更新时间）、出错和空数据（说明为什么空、下一步做什么）这几种状态。用 `data-states` 在屏幕上登记状态，用 `data-when` 显示相应内容，再用工具栏或 `data-state-to` 实际切换。
- 问题旁边放处理入口，如「查看名单」「发送提醒」，用 `data-go` 或 `data-open` 连到对应屏幕或弹窗。
- 卡片上只放名称、数字、单位和一两个词的比较基准（如「较上月」）；解释放到详情屏或折叠内容里。

## 交付前检查

1. 找一个已知的数核对，如上游给出的总数或用户提到的数，看页面上的 KPI 是否一致。`validate` 通过只说明计算自洽，不说明取数正确。
2. 运行 `htmlview shot report.html`，打开 `desktop-top.png` 和 `mobile-top.png` 检查：三秒内能否说出问题的答案；视线是否先落在被强调的问题上；有没有半空的卡片。
3. 每个视图都切换一遍，确认强调、目标线和图题仍然成立。
4. KPI 和图题里没有整句；叙述没有复述页面上已有的数。
