# 架构图

系统分层、模块边界和静态依赖使用本族。只表达结构，不暗示调用先后；有消息顺序时改用 `sequenceDiagram`，强调跨角色责任时用 `swimlane`。

## layers

原生 `layers` 每层最多 6 组、每组最多 30 项，最多 8 层；层名和能力项宽度受限（层名最大 160px、能力项最大 208px），过宽会报错。每层写 `- 层名 | 说明`，其下用 `- 分组: 能力项, 能力项`；也可用 `- 分类 > 能力项, 能力项`。分组可标 `{db}` 或 `{ext}`；能力项前缀 `+`、`~`、`=` 分别表示新增、改造、复用。顶层不能混合层与分组模式，能力项不能脱离所属层；名称过宽、语法错误或超限会报错，应修正结构而非删除事实。

## blocks

原生 `blocks` 表达嵌套容器与容器间依赖。支持 `row`、`col` 布局，最多嵌套 4 层、80 个容器、160 个能力项和 8 条关系；标签最多 24 字符、2 行，容器标题最多 3 行。`box 名称` 可含 `{db}` / `{ext}` 标记，能力项可写在 box 内；关系用顶格的 `A -> B: 标签`（同步）或 `A ~> B: 标签`（异步）。容器名必须唯一，关系端点必须能唯一解析，标签和图标须符合受控范围；未知节点、图标、无通道关系和超限均报错。相邻容器之间没有可用箭头通道时，调整容器顺序或改用其他关系图，不要假定渲染器会绕过遮挡。

```blocks
---
title: 订单服务依赖支付服务
---
row
  box 订单服务 {ext}
    查询订单, 校验状态
  box 支付服务
    创建退款, 通知渠道
订单服务 -> 支付服务: RPC 调用
订单服务 ~> 支付服务: 退款事件
```

## C4Context

C4、`architecture-beta`、`block-beta` 共用上限：40 个节点、60 条边、240 行。本型表达人员和系统的上下文关系；受控元素包括 `Person`、`Person_Ext`、`System`、`System_Ext`，可在一层边界块中分组。C4 类型共用 `Rel` / `Rel_L` / `Rel_R` / `Rel_U` / `Rel_D` 关系语法；边端点须存在。未知或不支持的语句报错，不会静默忽略。

## C4Container

表达系统内部容器及其静态依赖；受控元素包括 `Container`、`ContainerDb`、`ContainerQueue` 和 `System_Boundary`。关系语法与 `C4Context` 相同。该类型不自动补造系统、容器或依赖信息。

## C4Component

表达单个容器内部的组件边界和依赖，受控元素包括 `Component` 与适用的系统/容器边界。关系语法与 `C4Context` 相同；不要用它描述执行时间顺序，未知语句和无效端点报错。

## C4Dynamic

表达 C4 元素间有方向的交互关系；未编号关系会按声明顺序自动编号。关系语法与 C4 共用，但不支持任意 C4/Mermaid 扩展；最多 40 个节点、60 条边、240 行。

## C4Deployment

使用 `Deployment_Node` 表达部署节点与其所含 C4 元素；边界仅支持一层。最多 40 个节点、60 条边、240 行；不支持的语句报错。

## architecture-beta

支持 `group id(icon)[名称]`、`service id(icon)[名称] in groupId`、`junction id` 以及带端口的关系。图标限 `cloud`、`database`、`disk`、`internet`、`server`、`browser`；端口仅 `L`、`R`、`T`、`B`。分组不能嵌套。未登记图标、未知节点或不支持语法会报错；不要把其他 Mermaid 图标名当作可用值。

## block-beta

支持 `columns N`（N 为 1–8）、`block` / `block:id` 单层分组、`space` 占位、`id["名称"]` 或裸 ID，以及受控连接符 `-->`、`<-->`、`<--`、`---`、`==`、`--x`。明确列数后节点数不得多于列数，否则会报错（多行网格不支持）。最多 40 个节点、60 条边、240 行。

所有 Mermaid C4、`architecture-beta`、`block-beta` 示例可在源码中写前言区 `title`；关系图正文 `title` 也受支持。阅读文档须提供图题；应在源码写 `title`，而不是依赖图框外的说明。
